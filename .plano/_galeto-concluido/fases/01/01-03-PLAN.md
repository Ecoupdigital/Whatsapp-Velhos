# Fase 01 Plano 01-03: Suite de testes - prova de migracao nao-destrutiva e idempotente

**Objetivo:** Provar, de forma automatizada e repetivel, que a migracao da Fase 1 e (a) nao-destrutiva (MIG-05), (b) preserva a contagem de recebidos (MIG-04 / TEST-01) e (c) idempotente (TEST-06). Como o codebase nao tem suite de testes ainda, este plano cria a infra minima de testes (`backend/tests/`, `pytest.ini`, `conftest.py`) e os testes da Fase 1. O cenario simula o estado legado de producao: tabela `eventos` SEM a coluna `tipos_item`, participantes com numero / sem numero / vazios, e roda a migracao real sobre ele.

## Contexto

@backend/migrations.py - SUT (system under test), criado no plano 01-02. Importado como `import migrations`.
@backend/models.py - modelos (plano 01-01). Importado como `import models`.
@backend/database.py - `Base`. Os testes NAO usam o engine global; criam engine SQLite proprio por teste/fixture para isolamento.
@backend/requirements.txt - pytest NAO esta listado; precisa estar disponivel (pytest 9.x ja instalado no ambiente dev). Adicionar `pytest` em requirements.txt na secao de dev.

Pontos criticos do ambiente:
- Backend usa imports ABSOLUTOS (`from database import Base`). Logo, o pytest precisa ter `backend/` no `sys.path`. Resolver com `pytest.ini` contendo `pythonpath = .` e rodando pytest com cwd em `backend/`.
- O banco real `backend/velhos.db` NAO pode ser tocado pelos testes. Usar engine SQLite em arquivo temporario (`tempfile`) ou `:memory:` com mesma conexao.
- Para reproduzir o estado legado de producao (tabela `eventos` sem `tipos_item`), o conftest cria a tabela `eventos` manualmente SEM a coluna, em vez de usar `create_all` (que ja incluiria `tipos_item` apos o plano 01-01). Isso garante que o teste de ADD COLUMN exercite o caminho real.

def _criar_schema_legado(engine):

                id INTEGER PRIMARY KEY AUTOINCREMENT,
                tipo TEXT NOT NULL,
                titulo TEXT NOT NULL,
                created_at TEXT
            )

            CREATE TABLE evento_participantes (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                evento_id INTEGER NOT NULL,
                jogador_id INTEGER,

                status TEXT,

O fluxo padrao: snapshot de colunas legadas -> `Base.metadata.create_all(bind=engine)` (cria as 2 tabelas novas; tabela eventos ja existe e nao e alterada por create_all) -> `migrations.run_additive_migrations(engine)` -> asserts. Codigo:

```python
from sqlalchemy import inspect, func
from sqlalchemy.orm import sessionmaker

import models
import migrations
from database import Base


def _snapshot_colunas(engine):
    insp = inspect(engine)
    return {t: {c[\"name\"] for c in insp.get_columns(t)} for t in insp.get_table_names()}


def _migrar(engine):
    \"\"\"Cria tabelas novas (create_all nao toca eventos existente) + roda migracao.\"\"\"
    Base.metadata.create_all(bind=engine)
    migrations.run_additive_migrations(engine)


def test_mig05_estritamente_aditiva(legacy_engine):
    \"\"\"MIG-05: nenhuma coluna pre-migracao some; eventos e evento_participantes preservam tudo.\"\"\"
    antes = _snapshot_colunas(legacy_engine)
    _migrar(legacy_engine)
    depois = _snapshot_colunas(legacy_engine)
    for tabela, cols_antes in antes.items():
        assert tabela in depois, f\"tabela {tabela} sumiu\"
        faltando = cols_antes - depois[tabela]
        assert not faltando, f\"colunas removidas de {tabela}: {faltando}\"
    # colunas legadas especificas continuam
    ep = depois[\"evento_participantes\"]
    assert {\"numero_inicio\", \"numero_fim\", \"qtd_cartoes_recebidos\"}.issubset(ep)
    # coluna nova foi adicionada
    assert \"tipos_item\" in depois[\"eventos\"]


def test_test01_contagem_recebidos_preservada(legacy_engine):
    \"\"\"TEST-01 / MIG-04: sum(faixas.quantidade) == qtd_cartoes_recebidos legado por participante.\"\"\"
    S = sessionmaker(bind=legacy_engine)
    db = S()
    recebidos_antes = {p.id: (p.qtd_cartoes_recebidos or 0)
                       for p in db.query(models.EventoParticipante).all()}
    db.close()
    _migrar(legacy_engine)
    db = S()
    for pid, recebido in recebidos_antes.items():
        soma = (db.query(func.coalesce(func.sum(models.EventoCartaoFaixa.quantidade), 0))
                .filter(models.EventoCartaoFaixa.evento_participante_id == pid).scalar())
        assert soma == recebido, f\"participante {pid}: soma faixas {soma} != recebidos legado {recebido}\"
    db.close()


def test_test06_idempotencia(legacy_engine):
    \"\"\"TEST-06: rodar run_additive_migrations 2x nao duplica faixas nem falha no ADD COLUMN.\"\"\"
    Base.metadata.create_all(bind=legacy_engine)
    migrations.run_additive_migrations(legacy_engine)
    S = sessionmaker(bind=legacy_engine)
    db = S()
    faixas_1 = db.query(models.EventoCartaoFaixa).count()
    db.close()
    # 2a execucao
    migrations.run_additive_migrations(legacy_engine)
    db = S()
    faixas_2 = db.query(models.EventoCartaoFaixa).count()
    db.close()
    assert faixas_1 == faixas_2, f\"backfill duplicou faixas: {faixas_1} -> {faixas_2}\"
    # coluna ainda unica (ADD COLUMN nao re-executou nem falhou)
    cols = [c[\"name\"] for c in inspect(legacy_engine).get_columns(\"eventos\")]
    assert cols.count(\"tipos_item\") == 1


def test_backfill_ramos(legacy_engine):
    \"\"\"Confere os 3 ramos do backfill nos dados da fixture.\"\"\"
    _migrar(legacy_engine)
    S = sessionmaker(bind=legacy_engine)
    db = S()
    def faixas(pid):
        return db.query(models.EventoCartaoFaixa).filter_by(evento_participante_id=pid).all()
    f1 = faixas(1)  # numerado 10-21
    assert len(f1) == 1 and f1[0].sem_numero == 0 and f1[0].quantidade == 12
    f2 = faixas(2)  # sem numero, 5
    assert len(f2) == 1 and f2[0].sem_numero == 1 and f2[0].quantidade == 5 and f2[0].numero_inicio is None
    f3 = faixas(3)  # vazio
    assert len(f3) == 0
    f4 = faixas(4)  # numerado 100-100
    assert len(f4) == 1 and f4[0].quantidade == 1
    db.close()
```

Notas:
- `test_mig05` faz o snapshot ANTES de qualquer migracao (estado legado puro) e compara com o estado depois -> prova aditividade.
- `test_test06` chama a migracao 3x no total (1 dentro do helper + 2 explicitas) e garante contagem estavel + coluna unica.
- `create_all` NAO altera a tabela `eventos` ja existente (SQLAlchemy so cria tabelas faltantes), entao o ADD COLUMN da migracao e o unico caminho que adiciona `tipos_item` - exatamente o cenario de producao.
